# Theia 1.76 migration

RocKIT targets Theia 1.76.0 (previously 1.65.2). The target was verified against npm and the upstream release on 2026-10-26.

## Build environment

Use Node.js 24 or newer and Yarn 1.22.22. The migration machine now reports Node 24.22.1 after switching to NVM. CI uses Node 24. Electron is pinned to 42.8.1 to match `@theia/electron`.

All Theia dependencies and local packages that use Theia package names have matching versions. The `upstream.version` and `theia*BaseVersion` fields on the copied Navigator and Property View implementations deliberately retain 1.65.2: they record the origin of those sources, rather than the runtime version.

React, React DOM, and their types resolve to version 19 throughout the workspace. Extension TypeScript versions are aligned to 5.9.3. Both MUI trees use the React 19 compatible SimpleTreeView API; the JSON preview uses the maintained Microlink fork. RocKIT registers Ant Design 5's React 19 renderer and supplies `createRoot` before loading ReCrate's bundled Ant Design. The ReCrate submodule remains at its upstream commit with no source changes.

## Validation stages

Upgrade directly to the target version, validating at these boundaries. Installing every intervening minor version is only useful if a regression needs to be isolated.

1. `yarn install` and `yarn theia check:theia-version` on CI/Linux; use `yarn rebuild:electron` for a clean Windows rebuild
2. `yarn build:extensions` and `yarn test:unit`
3. `yarn build:browser` and `yarn build:electron`
4. `yarn test:e2e` and packaged application checks on Windows, Linux, and both macOS architectures

Theia 1.75 removed webpack. Application bundler configurations are generated by Theia; remove an old ignored `webpack.config.js` before building. Custom bundler settings must use `esbuild.mjs`. Clear old application `lib` outputs when first migrating so stale webpack native helpers cannot take precedence over the new prebuilds.

The upstream esbuild configuration now stages node-pty helpers and workers. RocKIT no longer overwrites its generated agent with the old copy script. Electron packaging extracts `lib/backend/native` and `lib/prebuilds` from asar so native executables can run. The macOS packaging preparation stages universal ripgrep and the target node-pty prebuilds using the new layout.

## Electron files locked during install or rebuild

A background RocKIT MCP server can keep this checkout's `node_modules/electron/dist/electron.exe` running after the desktop window closes. This can cause EBUSY while replacing Electron files. Inspect the process executable path and command line, and stop the matching development MCP server before installing or rebuilding. Restart that client connection after the build if needed. A PC restart is normally unnecessary. Do not stop unrelated Electron applications.

A separate Windows failure is `MSB8020: The build tools for ClangCL cannot be found` during `yarn install`. That is caused by Yarn's nested node-gyp 9 under Node 24, not by a file lock. The RocKIT `rebuild:electron` script installs without lifecycle scripts on Windows, builds its native modules with node-gyp 11, and then runs the normal application build. A PC restart does not address `MSB8020`.

## Validation on 2026-10-26

- Theia version consistency check passed for all 38 workspaces.
- Forced TypeScript builds passed for all custom extensions and rocrate-context-core.
- `yarn test:unit` passed in full (`.theia-upgrade-unit.log`).
- Browser esbuild bundle passed with ReCrate clean (`.theia-upgrade-recrate-clean-browser.log`).
- With ReCrate clean, its Vite/Rollup build and the RocKIT Electron bundle pass (`.theia-upgrade-recrate-clean-source.log`, `.theia-upgrade-recrate-clean-electron.log`); all 15 Electron end-to-end tests pass (`.theia-upgrade-recrate-clean-e2e-all.log`).
- After the browser bundle switched shared native modules to the browser target, `yarn workspace electron-app run rebuild` passed and a final normal-path Electron startup test passed (`.theia-upgrade-final-electron-native.log`, `.theia-upgrade-recrate-clean-final-startup.log`).
- The clean ReCrate build reports five React 19 declaration diagnostics from its upstream ref types, but Vite completes with exit code 0. No ReCrate source or test files were changed.
- `yarn install --frozen-lockfile --ignore-scripts --offline` passed (`.theia-upgrade-frozen-install.log`). Browser and Electron app manifests request the checked-out ReCrate workspace version 0.1.62. Electron and four Windows native modules were restored after this scripts-disabled check, and normal-path startup passed again, including after the packaging attempt (`.theia-upgrade-e2e-last.log`).
- After a normal clean install failed with `MSB8020` in Yarn's nested node-gyp 9, RocKIT's `rebuild:electron` script was changed on Windows to install without lifecycle scripts and build its four native modules with node-gyp 11. The complete `yarn rebuild:electron` command passed (`.theia-upgrade-rebuild-electron.log`).

The upgrade also fixes a startup preference race: the splash and update contributions await `PreferenceService.ready`. The E2E fixture disables workspace trust only in its isolated test profile.

## Remaining release checks

- Build/package the app on each release platform. The Windows clean rebuild now handles its native modules with node-gyp 11 because Yarn's nested node-gyp 9 selects unavailable ClangCL tooling with Node 24 here.
- Test packaged applications on Windows, Linux, and macOS x64/arm64. A Windows `electron-builder --win --dir` attempt rebuilt native modules but spent several minutes traversing the Yarn workspace dependency graph without creating `app.asar`; it was stopped and its partial output removed (`.theia-upgrade-win-package.log`). The macOS native staging code was updated but could not be executed on this Windows host.
- ReCrate is a separate Git submodule and is clean at its existing commit. Commit only RocKIT repository changes for this upgrade. No commits or pushes were made by Codex.

An earlier rebuild of the pre-existing `electron-app/lib` directory encountered an inaccessible generated `rg.exe`, even after no locking process remained. The subsequent full clean `yarn rebuild:electron` completed successfully.
