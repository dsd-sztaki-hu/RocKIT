Reviewing External RO-Crate Changes

RocKIT watches the open workspace's ro-crate-metadata.json file. When an AI client, MCP tool, or other external program modifies that file, RocKIT rereads it after a short delay, compares it with the loaded state, and starts the review workflow. Saves made by RocKIT itself are not treated as external changes.

Detection and Reloading​

The default behavior is to ask before reloading. RocKIT reports that ro-crate-metadata.json changed outside the application and offers three choices:

  • Reload: load the new version from disk.
  • Always Reload: load the new version and switch the user preference to automatic reload.
  • Ignore: keep the version currently loaded in RocKIT and write it back to disk.

The behavior is controlled by the rockit.roCrate.externalChangeAction preference. Supported values are:

  • prompt: ask before reloading.
  • auto: automatically load external changes.
  • off: do not start an automatic reload or review workflow for external changes.

If the external change leaves invalid JSON on disk, RocKIT does not load it. When a last valid in-memory RO-Crate is available, RocKIT offers to restore that version. If ro-crate-metadata.json is missing, RocKIT removes the related approval state, clears the loaded RO-Crate, and offers a recovery path.

Approval State​

When the external version is reloaded, RocKIT collects field-level differences between the previous RO-Crate and the new ro-crate-metadata.json. The comparison covers root-level properties and properties on entities in @graph.

Each difference becomes an approval item. The item records the affected entity, property name, operation (create, update, or delete), previous value when needed, timestamp, and whether the change has been approved. New or changed items are not approved by default.

Editor Actions​

The RO-Crate editor presents approval items as changes proposed by AI or an external tool. For each affected field, the user can decide to:

  • accept the suggestion when the externally written value is correct;
  • reject the suggestion when the previous value should be kept or restored;
  • manually edit the value when the suggestion is useful but needs correction.

These decisions are also recorded in RocKIT's history. Accepting a suggestion is labeled Accept AI suggestion, rejecting one is labeled Reject AI suggestion, and manual correction is labeled Edit AI suggestion. Reject and manual-edit actions are merged with the related metadata change in history, so the decision and the actual RO-Crate edit can be handled as one operation.

Recommended Use​

After working with AI or an external agent, always review the pending fields, then validate the crate and check the preview before saving. When automatic reload is enabled, reviewing the approval markers is especially important because the version on disk is loaded into RocKIT without a separate human confirmation step.
