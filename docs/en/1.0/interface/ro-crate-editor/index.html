Metadata Editor

The Metadata Editor is the form-based editor for one selected entity. It edits the RO-Crate JSON through structured fields instead of requiring manual JSON editing.

Form Structure​

Fields are grouped by the active profile and any metadata profiles associated with the entity. Basic RO-Crate properties appear in the Basic data section: this contains the @id, @type, and Name fields, followed by the profile-specific properties. Required fields are indicated by the form and by validation messages.

Entity identifiers are part of the crate's reference structure. Change @id values only when you understand the effect on links. For files and datasets, workspace-relative paths are usually the clearest identifiers in local crates.

The editor supports common field types including text, long text, numbers, dates, URLs, booleans, selections, entity references, and map-like values. A field can be added when the schema permits it and removed when the property is optional or repeatable.

Navigating Between Entities​

The left side of the editor header contains three navigation buttons. The back and forward arrows move through the editor's entity history, and are enabled only when there is a previous or next item in that history. The home icon opens the crate's root entity (./) and is disabled when that entity is already current. The arrow button on the right side of the header opens the linked-entities panel: it lists entities that reference the current entity and opens a selected item in the editor before closing.

Many RO-Crate properties refer to another entity rather than storing plain text. For example, an author can be a Person entity reused by several datasets or files. When editing a reference field, choose an existing entity when it already exists, or create a new linked entity when the metadata describes a new person, organization, place, URL, or other contextual object.

The editor also exposes reverse relationships: places where the current entity is referenced by other entities. Use those links to move from a person, organization, or URL back to the datasets or files that use it.

Quick Filtering​

The settings button on the right side of the editor header opens the quick filter bar. From this bar you can hide or show field help, hide empty fields, and filter fields by name or current value. When the entity has AI-edited fields, an additional filter button appears so only those fields can be listed.

Changes written directly to ro-crate-metadata.json by AI or another external program are also shown on the RO-Crate Editor fields, where they can be accepted, rejected, or manually corrected. The full flow is described in Reviewing external RO-Crate changes.

Adding Individual Fields​

Traditional profile association uses the + button on the left to add complete profile sections to the entity. Separately, the + Add button in the editor header can add individual metadata fields to the current entity.

The + Add button opens a property picker panel. There you can search by name, choose all loaded schemas or one specific schema, then add a schema.org property or a field from another loaded ontology. The Only show matching properties option shows only fields that fit the current entity type by default; when it is turned off, the full property list from the loaded schemas can be browsed.

Use the Schemas button to manage the ontologies available in the property picker. In addition to the built-in Schema.org schema, further schemas can be loaded or registered by URL, and you can set which RO-Crate versions they are active for.

Metadata Profile Handling​

Metadata profiles define additional domain- or repository-specific fields beyond the core RO-Crate properties. Use the profile rail on the left side of the editor to select a profile associated with the entity; the selected profile determines which profile-specific fields appear in the form. An entity can have multiple profiles, allowing fields from different schemas to be handled together.

Add a new profile to the entity being edited with the + button on the left side of the profile rail. For details about profile availability and configuration, see the Metadata Profile Manager page.

Reviewing AI Changes​

When an AI client or another external tool changes the RO-Crate, the editor marks the affected fields as AI changes that need review. Each suggestion can be accepted or rejected; accepting keeps the externally written value, while rejecting restores the previous value. See Reviewing External RO-Crate Changes for the detailed workflow.

Saving​

Changes are not persisted to the crate until you perform a save action. Save from the File menu with the Save command, or use the default Ctrl+S keybinding. After saving, the application records RO-Crate changes in history so undo and redo can reverse supported metadata edits during the current session.
