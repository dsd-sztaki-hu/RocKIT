# Plan: Lightweight Agent Instructions + Linked Workflow Docs

## Source Reference
This plan is informed by OpenAI's "Harness Engineering" article:

- https://openai.com/index/harness-engineering/

## Ideas Adopted from the Paper
We explicitly adopt these ideas and adapt them for RO-Crate operations in RocKIT:

1. Avoid one giant instruction file.
  - Keep `AGENTS.md`/`CLAUDE.md` short and task-orienting.
  - Move detailed procedures into focused docs.
2. Make guidance legible and navigable.
  - Bootstrap file points to specific workflow docs (profile-first, search, validation).
  - Agents can load only relevant guidance for the current step.
3. Reduce instruction rot.
  - Version-managed docs are generated/copied by RocKIT on launch.
  - Content is modular, so updates are localized and easier to maintain.
4. Support checkability and drift control.
  - Materialization behavior is tested (create/upgrade/preserve user section).
  - Workflow order is explicit and consistent across agent runs.

## Goal
Replace the current monolithic instruction approach with:

1. A short, stable `AGENTS.md` / `CLAUDE.md` bootstrap file.
2. A set of focused, versioned workflow docs.
3. Automatic materialization of both bootstrap + workflow docs into the target folder when an agent is launched from RocKIT (same lifecycle as current `AGENTS.md` / `CLAUDE.md` handling).

This plan applies to RO-Crate metadata curation flows using the `rocrate-mcp-server`.

## Why
- Large instruction blobs are hard for agents to follow reliably.
- Profile-first behavior is currently implicit and can be skipped in practice.
- Detailed guidance (search strategy, profile alignment, evidence handling, mutation safety) should be modular and checkable.
- Updating one focused doc is safer than editing one giant file.

## Target Behavior
When user starts any supported coding agent from RocKIT on a directory:

1. A short `AGENTS.md` or `CLAUDE.md` is ensured in the target directory.
2. A docs folder with curated guidance is also ensured in the same target directory.
3. The bootstrap file links to those docs and enforces execution order.
4. Existing user customizations are preserved during upgrades.

## Proposed Doc Set
Create a managed docs subtree (name can be finalized during implementation):

- `ROCKIT_AGENT_DOCS/profile-first-workflow.md`
- `ROCKIT_AGENT_DOCS/search-and-evidence.md`
- `ROCKIT_AGENT_DOCS/profile-alignment-rules.md`
- `ROCKIT_AGENT_DOCS/safe-mutations.md`
- `ROCKIT_AGENT_DOCS/validation-and-dataverse-gate.md`
- `ROCKIT_AGENT_DOCS/checklists.md`

### Required workflow emphasis
`profile-first-workflow.md` must make this mandatory sequence explicit:

1. `get_rocrate_context`
2. Resolve profile constraints (`profileRules` and/or `resolve_profile_schema`)
3. Build required/optional metadata plan
4. Search only for missing planned values
5. Apply minimal changes with MCP write tools
6. `read_crate` verification
7. `validate_crate` (`allow_missing` iteratively, `enforce_required` before publication)

## Scope of Changes

### 1) Template and content split
- Refactor `theia-extensions/file-explorer/AGENTS.template.md` into:
  - concise bootstrap content
  - links to managed docs
- Keep managed marker logic so user-added local rules remain below managed section.

### 2) Managed doc assets in file-explorer extension
- Add canonical managed docs under the extension source (for example `theia-extensions/file-explorer/agent-docs/`).
- Add a generation step similar to `scripts/generate-agents-template.js` if needed, so docs are available in built artifacts.

### 3) Materialization on agent launch (critical requirement)
- Extend `ensureAgentInstructionsFile(...)` flow in
  `theia-extensions/file-explorer/src/electron-browser/electron-navigator-menu-contribution.ts`
  to also call a new method, e.g. `ensureAgentDocsBundle(directoryUri)`.
- `ensureAgentDocsBundle` should:
  - create docs directory in target folder if missing
  - copy/update managed docs files
  - avoid clobbering user edits unexpectedly (see update policy below)

### 4) Update policy
- Keep bootstrap file auto-upgradable with current managed marker approach.
- For bundled docs, use one of:
  - strict managed overwrite (simple, deterministic), or
  - marker-based managed section + user extension block.
- Recommendation: start with strict managed overwrite for docs + clear header note (`AUTO-GENERATED BY RocKIT`) to reduce drift.

### 5) Tests
- Add/extend tests to verify:
  - first launch creates bootstrap + docs bundle
  - relaunch upgrades managed content
  - user custom block in `AGENTS.md`/`CLAUDE.md` is preserved
  - docs are present for both `AGENTS.md` and `CLAUDE.md` paths

### 6) Documentation
- Update relevant README sections in `file-explorer` and optionally root docs to describe:
  - new docs structure
  - where generated files appear in user project folders
  - how users can safely add local rules

## Acceptance Criteria
- Launching agent from RocKIT into a folder creates/updates:
  - `AGENTS.md` (or `CLAUDE.md` for Claude)
  - managed docs bundle directory
- Bootstrap file is lightweight and links to modular docs.
- Profile-first workflow is explicit and discoverable.
- Existing user customizations in bootstrap file are preserved.
- Regression tests pass.

## Rollout Plan

1. Introduce docs bundle + lightweight bootstrap template.
2. Implement copy/materialization logic in launch path.
3. Add tests for create/upgrade behavior.
4. Update extension docs.
5. Dogfood with 2-3 real RO-Crate curation tasks and refine wording.

## Risks and Mitigations
- Risk: docs drift from MCP behavior.
  - Mitigation: keep docs short, tied to tool names, and tested via launch materialization tests.
- Risk: user confusion from generated files.
  - Mitigation: clear header in generated docs and single directory for all managed files.
- Risk: accidental overwrite of user-edited managed docs.
  - Mitigation: document policy clearly; optionally add user suffix section in phase 2.

## Out of Scope (for this phase)
- Changing MCP server tool semantics.
- Enforcing workflow order at protocol level (this plan addresses agent guidance and launch-time materialization first).
